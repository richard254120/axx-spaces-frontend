Single-package Expo app (entry `App.js` → `node_modules/expo/AppEntry.js`) targeting Android/iOS/web via `app.json`. The runtime is split into two parallel UI layers:
- App Router layer (`src/app/`) using Expo Router (`_layout.tsx`, `index.tsx`, `explore.tsx`) for the web/desktop entry.
- Classic React Navigation layer (`src/navigation/AppNavigator.js`) wrapping a `NavigationContainer` + `createStackNavigator` that hosts the legacy screens under `src/screens/`.

Feature ownership follows a flat domain layout: each top-level domain (properties, tourism, business, materials, movers, wallet, notifications, profile) has its own screen file plus a matching API namespace in `src/services/api.js` (`propertyAPI`, `tourismAPI`, `businessAPI`, `materialsAPI`, `moversAPI`, `walletAPI`, `notificationAPI`, `userAPI`). Authentication state lives in `src/context/AuthContext.js` (React Context + `expo-secure-store` for tokens, `@react-native-async-storage/async-storage` for user data). Platform-specific code uses the `.web.tsx` suffix convention (`animated-icon.web.tsx`, `app-tabs.web.tsx`, `use-color-scheme.web.ts`).

Native capabilities are delegated to dedicated service modules (`cameraService`, `locationService`, `notificationService`, `offlineService`, `cacheService`) rather than being imported directly inside screens. The Android native shell under `android/` is generated by Expo but kept in-tree with `usesCleartextTraffic: true` and explicit permissions for camera, storage and location.
